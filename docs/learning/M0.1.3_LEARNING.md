# M0.1.3：在本机理解功率与能量

本步已实现 Python 设备模拟器。输入是场景和时间，输出是带单位、UTC 时间和质量的原始读数。它还没有接入后台轮询、消息总线或历史数据库。

## 先运行本步演示

在解压后的 `microgrid_ems` 根目录打开终端：

```powershell
python ems.py doctor
python -m unittest discover -s tests -v
python ems.py demo-simulator
```

应显示 READY_M01、43 项测试 OK，Demo 的 result 为 PASS。使用虚拟时间，不用等真实的一小时。输出中的 UTC 时间从场景 startTime 开始，并不是当前实时时钟。

| 操作 | Load | PV | ESS | EV | PCC | SOC |
|---|---:|---:|---:|---:|---:|---:|
| 初始 | 500 | 0 | 0 | 0 | 500 | 60% |
| 光伏增至 300 | 500 | 300 | 0 | 0 | 200 | 60% |
| 光伏增至 350 | 500 | 350 | 0 | 0 | 150 | 60% |
| 储能放电 100 | 500 | 350 | +100 | 0 | 50 | 60% |
| 放电持续 1h | 500 | 350 | +100 | 0 | 50 | 50% |
| 改为充电 100 | 500 | 350 | -100 | 0 | 250 | 50% |
| 充电持续 1h | 500 | 350 | -100 | 0 | 250 | 60% |

功率列单位为 kW。Load 不含 EV；PCC 正数为购电，负数为送电；ESS 正数为放电、负数为充电。

功率平衡：`PCC = Load + EV - PV - ESS`。
理想能量：`E_new = E_old - ESS_kW × 时间小时数`，`SOC = 100 × E / 容量kWh`。
例：1000kWh 容量的 60% 是 600kWh；放出 100kWh 后剩 500kWh，即 50%。这里下降的是 10 个百分点。

## 自己做一次实验

包内已有放电场景，不需要先编辑文件：

```powershell
python ems.py simulate --scenario configs/scenarios/discharge.json --seconds 3600
```

查看 final：soc=50、energyKwh=500、essKw=100、pccKw=50。measurements 中有 Load/PV/ESS/PCC/EV 功率和 SOC 共六个读数。

把 seconds 改为 1800，预期 SOC=55%；改为 25200（7h），预期 SOC=0%、essKw=0、pccKw=150。储能在第 6h 已空电，此后实际放电为零。输出的 requestedEssKw 仍为场景请求100，essKw才是瞬时实际功率；跨越空电边界时，不能用最后瞬时功率乘整个时长来算能量。

复制 discharge.json 为自己的文件，将 initialScenario.essKw 改为 -100，运行 3600 秒，初始60%会变成70%，PCC变成250。保留 demo.json 原样，标准演示会检查冻结的数值。

可选随机实验：给自建场景的 pvVariationKw 设置20，光伏会在基准±20kW内每个虚拟秒取一个确定值。相同 seed、场景与时间可复现；读取顺序和次数不改变结果。扰动代表物理光伏变化，PCC 使用同一个值保持功率平衡，不是独立的仪表误差。

## 断线究竟意味着什么

标准 Demo 最后在储能放电时断开其通信，推进1h。读取会失败，模拟储能仍继续放电，SOC从60%到50%。恢复连接并成功读取后才取得新值和新时间。

本步不会用 GOOD=0 替代失败，也不会凭恢复连接制造遥测。OFFLINE旧值、STALE计时、重连策略和统一 TelemetrySample 封装是 M0.1.4 Gateway 的工作。TIMEOUT故障是立即抛出的模拟异常，不是已验证800ms真实阻塞超时。

## 当前简化条件

- 每类资源一个聚合设备；设备 ID 固定 load01/pv01/ess01/pcc01/ev01，站点 ID 可配置。
- 效率为1，忽略损耗、自放电、衰减、斜率和温度；SOC物理范围0～100。满/空方向饱和仅描述理想模型，不是已实现保护或 EMS 控制策略。
- 场景设置是实验输入；不是给设备下发控制命令。没有真实设备、网络服务、GUI或自动轮询。
- 原来的 `run`/`demo` 仍演示 M0.1.1 生命周期；新模拟器由 `demo-simulator`/`simulate` 单独运行，完整链路按后续阶段接入。
