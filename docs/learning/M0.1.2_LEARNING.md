# M0.1.2 学习与本机验收

本步学习数据的含义，不运行发电或储能物理仿真。

1. 打开 `contracts/examples/soc_tag.json`。它是点表定义：SOC 单位 %、数值范围 0～100、每 1000ms 采样。定义没有“当前测量值”。
2. 打开 `telemetry_good.json`。payload 是一次测量：SOC=60、GOOD，timestamp 是测量时间；receivedAt 是接收时间。外层 schemaVersion 是消息格式版本，configVersion 是配置版本，两者不同。
3. 对比 `telemetry_offline.json`。值仍为 60，timestamp 完全相同；quality 改为 OFFLINE，qualityTimestamp、receivedAt、事件/样本 ID 和 sequence 更新。这是一次新的质量事件，不是一次新的 SOC 测量。
4. 打开 `snapshot.json`。ess.soc 指向 tags 中的测点；值与质量不能分离。PCC 缺失，不能默认为 0；该样例不能用于控制。

在解压后的项目根目录运行：

```text
python ems.py doctor
python -m unittest discover -s tests -v
python ems.py demo-contracts
```

预期环境 READY_M01，测试全部 OK；Demo 显示 result=PASS、sampleTimestampPreserved=true、snapshotControlEligible=false，以及 GOOD/OFFLINE 两组数据。Demo 是确定性的历史样例，时间不需要等于当前系统时间。

学习实验：备份或复制样例，再把 GOOD 的 value 改成 null 或 101，重跑 Demo 应非零退出且指出 value；把 schemaVersion 改成 2 应指出 schemaVersion。完成后还原文件，不把实验改坏的样例上传。测试使用独立构造数据，也覆盖这些失败场景。

验收时请确认你能解释：为什么 0 不等于缺失、为什么 OFFLINE 的 60% 不能当作实时 SOC、为什么改外部字典不能改掉已生成快照。用户确认本步后再进入 M0.1.3 Simulator，届时才演示 PV/PCC 功率变化和 SOC 积分。

## 更新本机与 GitHub

这是完整源码包。在一个新目录解压验证，再将源码合入你原来的本机仓库，保留原仓库 `.git` 和自己的 runtime 数据；不要把旧源码层层嵌套到包目录里。项目版本为 0.1.2.dev1。

本轮没有修改 GitHub。此前 GitHub 上传了 runtime 和 __pycache__；新包包含 `.gitignore`、`.gitattributes`，上传时也要保留这两个点开头的文件。已经被 Git 跟踪的生成文件不会因新增忽略规则自动消失：确认它们只是运行产物后，可在本机仅取消对这些文件的跟踪，再随本阶段源码更新提交；无需删除本机运行数据。本包不包含它们。
